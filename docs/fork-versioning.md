# Версии и релизы форка

Версии форка выдаёт workflow `.github/workflows/fork-release.yml`. Руками версию не правят:
файл `VERSION` принадлежит оригиналу и меняется только при синхронизации (`fork/sync_upstream.py`).

## Формат

`<VERSION оригинала>-ru.<N>`, например `1.0.36-ru.1`, затем `1.0.36-ru.2`. Тег: `v1.0.36-ru.2`.

- `N` растёт на каждый релиз при той же версии оригинала.
- После синхронизации с новой версией оригинала `N` начинается с 1 (`1.0.37-ru.1`).
- Если на коммите `main` уже стоит тег `v<VERSION>-ru.*`, повторный запуск ничего не выпускает.

## Когда выходит релиз

- Автоматически при каждом пуше в `main`, кроме правок только `*.md`, `docs/**` и `.github/README.md`.
- Вручную: **Actions → Fork release → Run workflow** (можно выбрать `targets`, по умолчанию `aarch64`).

## Что делает workflow

1. `version`: вычисляет версию и тег по существующим тегам.
2. `apk`: вызывает `android-debug.yml` (тот же workflow, что запускается вручную). Сборка подписана
   общеизвестным debug-ключом из `tools/android/ratspeak-debug-keystore.base64`, секреты не нужны,
   пакет ставится рядом с оригиналом как `org.ratspeak.android.ru`.
3. `release`: создаёт тег и GitHub Release, прикладывая файлы `Ratspeak-ru-<версия>-<abi>.apk`
   и `checksums.txt` отдельными файлами, а не архивом. В описание попадает список коммитов с прошлого релиза.

Нужный файл для большинства телефонов: `*-arm64*.apk`.

## Ограничения

- Debug-ключ публичный: любой, у кого он есть, может подписать «обновление» этого приложения.
  Релизы предназначены для личной установки, а не для распространения.
- Номер версии не вшит внутрь приложения: `versionName` берётся из конфигурации оригинала.
  Версия форка видна в имени тега, релиза и APK-файла.
