# Синхронизация с оригиналом (ratspeak/Ratspeak)

Форк устроен так, чтобы обновление из оригинала проходило **без ручного разбора конфликтов**.

## Правила

1. **Код форка живёт в своих файлах.** Новые модули, скрипты, стили, тесты и документация
   лежат в файлах, которых нет в оригинале (`connection_*.js`, `ru_*.js`, `announce_radar.js`,
   `route_lookup.js`, `contacts_backup.js`, `ratspeak-ru.css`, `connection_deep_link.rs`,
   `commands/connection_link.rs`, `fork_contracts.rs`, `docs/connection-links.md`, `tools/i18n`, `fork/`).
   Git не может конфликтовать там, где оригинал ничего не менял.
2. **В файлах оригинала допустимы только «крючки»**: одна-две строки, которые подключают
   код форка. Все они описаны в [`hooks.json`](hooks.json) и применяются скриптом
   [`apply_hooks.py`](apply_hooks.py). Править файлы оригинала руками нельзя: правка
   пропадёт или вызовет конфликт при следующем обновлении. Нужна новая точка входа,
   значит, добавьте хук.
3. **Корневые `README.md` и `CHANGELOG.md` остаются как в оригинале.** Описание форка:
   [`.github/README.md`](../.github/README.md) (GitHub показывает его первым), изменения
   форка: [`CHANGELOG-ru.md`](../CHANGELOG-ru.md).
4. **Интерфейс расширяется обёртками.** `ru_loader.js` один раз подключается в
   `index.html`, добавляет стили, блоки интерфейса (по якорям `#settings-backup-identity-btn`,
   `#network-activity`) и скрипты форка. `ru_extensions.js` оборачивает глобальные функции
   оригинала (`buildIfaceActionItems`, `actionPopover`) и подписывается на события.
   Тест `scripts/dashboard/test_fork_overlay.js` проверяет, что все якоря в файлах оригинала
   на месте, и называет тот, который пропал.

## Как обновиться

```sh
git remote add upstream https://github.com/ratspeak/Ratspeak.git   # один раз; скрипт сделает сам
python3 fork/sync_upstream.py --dry-run --run-tests   # репетиция в отдельной рабочей копии
python3 fork/sync_upstream.py --run-tests             # настоящее слияние upstream/main
python3 fork/sync_upstream.py --ref v1.0.40           # или конкретная метка оригинала
python3 fork/sync_upstream.py --run-tests --push-tags # то же и опубликовать релизные теги оригинала (vX.Y.Z) в форк
```

Скрипт добавляет `upstream`, делает `git fetch`, сливает ветку, а для каждого конфликтного файла
с хуком берёт версию оригинала и заново применяет хуки (то же самое сделал бы человек).
Затем он проверяет, что все хуки на месте, показывает новые строки интерфейса без перевода,
при `--run-tests` запускает тесты дашборда и коммитит слияние. Конфликт в любом другом файле
останавливает работу и выводится списком.

После слияния:

1. Переведите новые строки: `tools/i18n/README.md` (`extract.py`, `merge.py`, `build.py`).
2. Если менялся публичный API `ratspeak-tauri`, обновите снимок (`tools/check-api-baseline.py --update`
   на nightly из `api/stability.json`); `apply_hooks.py` пересчитывает счётчик и хэш сам.
3. Запустите CI (`cargo fmt`, `clippy`, `cargo test`, сборка Android).

## Если хук перестал применяться

Сообщение вида `lib-handlers: anchor '...' matches 0 lines in src-tauri/src/lib.rs` значит, что
оригинал переписал то место, к которому привязан хук. Откройте `hooks.json`, найдите хук по `id`,
подберите новый якорь (короткая уникальная строка рядом) и запустите
`python3 fork/apply_hooks.py`. Проверка без изменений: `python3 fork/apply_hooks.py --check`.

## Почему так

Хуки привязаны к тексту, а не к номерам строк, и вставляют код **рядом** с аналогичным кодом
оригинала (например, обработчики ссылок на каналы), поэтому обычно переживают его обновления.
Всё, что не помещается в одну-две строки, вынесено в отдельные файлы.
